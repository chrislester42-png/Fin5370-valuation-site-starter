# Rules for this project

This is a two-person FIN 5370 team project: an interactive equity valuation site for [COMPANY] ([TICKER]), built one section per module.

## Layout
- `research/memos/` holds the team's milestone memos. `research/sources/` holds source notes. `research/sources.md` is the source registry.
- `workbook/` holds the team's Q&D workbook. It is the only source of financial numbers for the site.
- `site/` is the published site: plain HTML, CSS, and JavaScript. No build step, no frameworks, no package installs. Libraries only from a CDN, and only when asked.
- `site/content.js` holds the words for each section. `site/data/financials.js` holds the numbers and is generated by `scripts/workbook_to_data.py`. Never hand-edit a generated file.

## Sections and their modules
thesis (1) · financials (2) · vault, shown as "Knowledge Bank" (3) · valuation (4) · theCall (5) · scorecard (6) · process (7) · tearsheet.html, glossary.html, sources.html (8)
Sections not yet built show "Coming in Module N." Touch only the section the current task names.

## Numbers
- Every number on the site traces to the workbook, a memo, or a source in `research/sources.md`. If a number has no source, do not write it; list it under "Numbers we still need" and tell the user.
- Never invent a figure, a date, a URL, or a quote. Say "I could not find this" instead.
- Each number in the Knowledge Bank carries a tier: Reported (from a filing or dataset as published), Derived (calculated from reported numbers, show the formula), or Estimate (a judgment call, name who made it and why).

## Working style
- Before changing files, state the plan in plain English and wait for a go-ahead.
- Explain what you did in plain English after each task. The user is new to this tool.
- Keep site copy short: forty words or fewer per block, headlines of eight words or fewer.
- No em-dashes in anything you write.

## Git
- On "sync": run `git pull`, then summarize what changed in plain English. Stop on any conflict and explain it.
- On "wrap up": add today's rows to `AI Log.md` (show them first), regenerate `site/data/financials.js` if the workbook changed, commit with a one-line message, push, and confirm the push finished.
- Never force-push. Never delete a branch. Never commit files larger than 20 MB.
- If a push fails, tell the user to click Push in GitHub Desktop.

## Safety
- Never ask for or store passwords, tokens, or API keys. Nothing in this repo is secret.
- Only public filings and public data.
